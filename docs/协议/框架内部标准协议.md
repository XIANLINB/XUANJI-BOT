# 璇玑框架内部标准协议（Framework Internal Standard Protocol）

> **定位**：璇玑框架的「普通话」。框架核心业务逻辑**只依赖本协议**，完全屏蔽 QQ 官方 API、OneBot 11 以及未来 KOOK / 微信 / Discord 等平台的差异。
> **一句话**：平台适配器负责把「方言」翻译成「普通话」（入站），框架核心只说普通话干活，再翻译成方言发出（出站）。
> **版本**：v1.0（草案） · 2026-08-10

---

## 1. 协议概述

### 1.1 核心思想

```
┌─ 平台层（方言）  ：QQ / OneBot / KOOK / 微信 / Discord ...
├─ 适配层（翻译官） ：每平台一个「事件转换器」+「发送实现」⇄ 平台 API
├─ 核心层（普通话中心）：BotPipeline / 命令 / 定时 / 存储 / 安全
│        ↑ 唯一标准：XuanJiEvent（入）+ XuanJiMessage（出）
├─ 能力层：LLM 引擎 / 插件（同一标准接入，可选可不选）
└─ 控制台层：Console API（同源管理）
```

**关键约束**：
- 核心层**禁止**出现任何平台字段（`user_id`/`group_openid`/`[CQ:at]`/`<@!...>` 等）。
- 适配器承担全部「取数据、填字段、转协议、调 API」的脏活。
- 核心只认识三样东西：**信封（XuanJiEvent）**、**消息内容（XuanJiMessage）**、**动作指令（XuanJiMessageSender 方法）**。

### 1.2 三件事模型

| 三件事 | 协议承载 | 状态 |
|---|---|---|
| ① 信封（所有事件统一格式） | `XuanJiEvent` + `XuanJiEventType` | ✅ 已实现 |
| ② 消息内容（说了什么 / 谁说的） | `XuanJiMessage` + `XuanJiMessageElement` + `XuanJiUser`/`XuanJiGroup` | ✅ 已实现 |
| ③ 动作指令（怎么回复 / 怎么操作） | `api.XuanJiMessageSender`（发消息 + 撤回/踢人/禁言/审批…） | ⚠️ 发消息已实现，动作类待补 |

### 1.3 标准模型清单（均在 `xuanji-api`）

| 模型 | 文件 | 职责 |
|---|---|---|
| 信封 | `api/event/XuanJiEvent.java` | 统一事件（事件ID/类型/机器人/发送者/群/消息/回执引用/透传） |
| 事件类型 | `api/event/XuanJiEventType.java` | 统一事件类型枚举（message/notice/request/interaction） |
| 统一用户 | `api/event/XuanJiUser.java` | 发送者（id/平台原始ID/昵称/框架角色/权限值） |
| 统一群 | `api/event/XuanJiGroup.java` | 群/频道（id/所属bot/平台群号/群名/人数） |
| 统一机器人 | `api/adapter/XuanJiBot.java` | 机器人实例（platform/selfId/status/capabilities） |
| 消息链 | `api/message/XuanJiMessage.java` | 富文本消息链（元素列表 + 便捷访问） |
| 消息元素 | `api/message/XuanJiMessageElement.java` | 14 种元素（sealed，编译器穷尽匹配） |
| 媒体五态 | `api/message/XuanJiMediaRef.java` + `XuanJiMediaForm.java` | URL/本地文件/base64/dataURI/平台ID 五态归一化 |
| 发送目标 | `api/sender/XuanJiTarget.java` | Private / Group / Guild |
| 发送回执 | `api/sender/XuanJiSendReceipt.java` | 平台消息ID/耗时/成功/失败原因 |
| 发送服务 | `api/sender/XuanJiMessageSender.java` | 统一动作出口（reply/send + 动作类） |

## 2. 信封标准（入站：所有事件）

### 2.1 XuanJiEvent

```java
public record XuanJiEvent(
    String eventId,            // 全局唯一事件ID（幂等去重用）
    XuanJiEventType type,            // 统一事件类型
    XuanJiBot bot,                   // 接收事件的机器人实例
    XuanJiUser sender,         // 发送者（私聊=对方，群聊=发言成员）
    XuanJiGroup group,         // 所属群/频道（私聊=null）
    XuanJiMessage message,      // 统一消息链（非消息事件=null）
    String replyToMsgId,       // 被动回复时引用的原始消息ID
    JsonNode platformData,     // 平台原始数据透传（精细场景/调试用）
    String rawXuanJiEventType,       // 平台原始事件类型字符串（分发路由用）
    String envType             // 环境（SANDBOX / PRODUCTION）
) {
    public boolean isGroupEvent()   { return group != null; }
    public boolean isMessageEvent() { return message != null; }
}
```

**约定**：
- `platformData` 保留平台原始 JSON，仅用于**调试、透传、Handler 精细场景**；核心业务不得依赖它。
- `rawXuanJiEventType` 是分发路由键（如 `GROUP_AT_MESSAGE_CREATE` / `C2C_MESSAGE_CREATE`），由 EventDispatcher 按它匹配 Handler。
- 入站链路：`平台WS/Webhook → 转换器 → XuanJiEvent → BotPipeline（各阶段）`。

### 2.2 XuanJiEventType 枚举

```java
public static final XuanJiEventType MESSAGE_PRIVATE     = new XuanJiEventType("message", "private");
public static final XuanJiEventType MESSAGE_GROUP       = new XuanJiEventType("message", "group");
public static final XuanJiEventType MESSAGE_GUILD       = new XuanJiEventType("message", "guild");
public static final XuanJiEventType NOTICE_MEMBER_JOIN  = new XuanJiEventType("notice", "member_join");
public static final XuanJiEventType NOTICE_MEMBER_LEAVE = new XuanJiEventType("notice", "member_leave");
public static final XuanJiEventType NOTICE_GROUP_SETTING= new XuanJiEventType("notice", "group_setting");
public static final XuanJiEventType REQUEST_GROUP_INVITE= new XuanJiEventType("request", "group_invite");
public static final XuanJiEventType REQUEST_FRIEND_ADD  = new XuanJiEventType("request", "friend_add");
public static final XuanJiEventType INTERACTION_BUTTON  = new XuanJiEventType("interaction", "button");
public static final XuanJiEventType INTERACTION_FORM    = new XuanJiEventType("interaction", "form");
```

**设计说明**：`XuanJiEventType` 是**类**（非 enum），`XuanJiEventType.parse("message/group")` 可从字符串还原——天然支持未来扩展，新增平台事件**只加常量，不改结构**。

**扩展预留（待实施）**：频道域（KOOK/Discord 为频道制）与细化：
```
MESSAGE_CHANNEL（频道消息）
NOTICE_CHANNEL_JOIN / NOTICE_CHANNEL_LEAVE（进/退频道）
NOTICE_GROUP_ADMIN_CHANGE（管理员变更，对应 OneBot group_admin）
NOTICE_FILE_UPLOAD（文件上传）
REQUEST_GROUP_APPLY（加群申请，区别于群邀请）
NOTICE_GROUP_POKE（戳一戳）等
```

## 4. 消息内容标准（说了什么 / 谁说的）

### 4.1 XuanJiMessage
```java
public record XuanJiMessage(List<XuanJiMessageElement> elements) {
    public static XuanJiMessage text(String content)   // 快捷构造纯文本
    public String plainText()                          // 拼接纯文本（日志/过滤）
    public boolean isAtBot()                           // 是否@了机器人
    public List<XuanJiMessageElement.Media> medias()         // 媒体元素列表
    public boolean has(Class<? extends XuanJiMessageElement> type)
    public String summary()
    // Builder：text / at / atAll / image / face / quote / reply / markdown / add
}
```

### 4.2 消息元素（14 种，sealed）
```java
sealed interface XuanJiMessageElement permits
    Text, At, Image, Face, Quote, Reply, Voice, Video, File,
    Markdown, Keyboard, Ark, Passthrough, Media
```
| 元素 | 说明 | 典型平台来源 |
|---|---|---|
| `Text(content)` | 纯文本 | 双方 |
| `At(userId, display)` | @某人；`At.all()` = @全体 | QQ mentions / OneBot [CQ:at] |
| `Image(url, fileMd5, w, h, size)` | 图片（实现 Media） | QQ attachments / OneBot [CQ:image] |
| `Face(faceId)` | 小黄脸/表情 | 双方 |
| `Quote(msgId, senderId, preview)` | 引用消息 | 双方 |
| `Reply(targetMsgId)` | 回复消息 | 双方 |
| `Voice(url, duration)` | 语音（实现 Media） | QQ voice_wav_url / OneBot [CQ:record] |
| `Video(url, duration, w, h)` | 视频（实现 Media） | 双方 |
| `File(url, name, size)` | 文件（实现 Media） | OneBot [CQ:file] |
| `Markdown(content, nativePayload)` | Markdown 卡片 | QQ 官方 |
| `Keyboard(nativePayload)` | 按钮键盘 | QQ 官方 |
| `Ark(templateId, nativePayload)` | ARK 卡片 | QQ 官方 |
| `Passthrough(platform, description, nativePayload)` | 平台特有内容透传 | 未知元素兜底 |
| `Media`（接口） | 媒体统一抽象（Image/Voice/Video/File 实现） | — |

**要点**：`sealed` 保证适配器用 pattern-matching switch 时**编译器强制穷尽**所有元素，新增元素类型会强制所有转换器补全——从编译期防止"漏翻译方言"。

### 4.3 媒体五态归一化（XuanJiMediaRef）
不同平台把同一份媒体以不同形态给框架，统一归一为**五种形态**，插件只读 `XuanJiMediaRef.form()` 即可判断，不必为每平台写下载逻辑：

```java
enum XuanJiMediaForm { URL, FILE_PATH, BASE64, DATA_URI, PLATFORM_ID }
record XuanJiMediaRef(XuanJiMediaForm form, String raw, MediaType type) {}

// 用法
XuanJiMessageElement.Media m = ...;
XuanJiMediaRef ref = m.resolve("qq");      // 按平台归一化
if (ref.form() == XuanJiMediaForm.PLATFORM_ID) { /* 平台文件标识 */ }
XuanJiMediaRef local = m.resolveFile("qq", botKey);  // 按需下载落盘（内容哈希去重 + TTL清理）
```

## 5. 动作指令标准（出站：怎么回复 / 怎么操作）

### 5.1 统一出口 api.XuanJiMessageSender
```java
interface XuanJiMessageSender {
    // ── 发消息（已实现） ──
    XuanJiSendReceipt reply(XuanJiMessage chain);              // 被动回复（自动带 msg_id 引用）
    XuanJiSendReceipt send(XuanJiTarget target, XuanJiMessage chain);// 主动发送（定时/跨会话）

    // ── 动作类（待补，能力位守卫） ──
    XuanJiSendReceipt recall(XuanJiTarget target, String msgId);                      // 撤回
    XuanJiSendReceipt kick(XuanJiTarget.Group group, String userId);                  // 踢人
    XuanJiSendReceipt mute(XuanJiTarget.Group group, String userId, int seconds);     // 禁言（0=解除）
    XuanJiSendReceipt approve(XuanJiTarget target, String requestId, boolean accept); // 审批加群/好友请求
    XuanJiSendReceipt setCard(XuanJiTarget.Group group, String userId, String card);  // 改群名片
}
```
**约定**：
- 平台不支持的动作：实现方返回 `XuanJiSendReceipt.fail("平台不支持 xxx", elapsed)`，**不抛异常**，由核心决定降级策略。
- 核心用 `XuanJiBot.capabilities` 判断能力，避免无效调用。

### 5.2 发送目标 XuanJiTarget
```java
sealed interface XuanJiTarget permits XuanJiTarget.Private, XuanJiTarget.Group, XuanJiTarget.Guild {
    record Private(String openid) {}     // 单聊
    record Group(String groupOpenid) {}  // 群
    record Guild(String channelId) {}    // 频道
}
```

### 5.3 发送回执 XuanJiSendReceipt
```java
record XuanJiSendReceipt(String platformMsgId, long elapsedMs, boolean success, String errorMessage) {
    static XuanJiSendReceipt ok(String platformMsgId, long elapsedMs);
    static XuanJiSendReceipt fail(String errorMessage, long elapsedMs);
}
```

### 5.4 专用方法保留（占位，不实现）
LLM 图片/视频/音频的理解与生成，未来统一走 XuanJiMessage 元素承载（`Image(bytes)` / `Voice(bytes)` 等）；同时**保留**以下专用方法签名作为占位（当前默认抛 `UnsupportedOperationException`），供字节级媒体直传的极端场景使用：
```java
// LlmReplySink（已存在，保持）
default void replyVoice(XuanJiEvent e, byte[] audio, String format, String fallback)
default void replyImage(XuanJiEvent e, String imageUrl, String fallback)
default void replyImageFile(XuanJiEvent e, byte[] image, String fallback)
```

## 6. 事件流转总览

### 6.1 入站
```
平台 WS/Webhook 原始 JSON
  → 转换器（翻译官）：
      QqEventConverter.convert() / OneXuanJiEventConverter.convert()
  → XuanJiEvent（普通话）
  → BotPipeline.proceed(be)（按 order 跑全部阶段）
      PreProcess → Waking(10) → ContentSafety(40) → llm-audit(41)
      → group-activity(44) → user-profile(45) → Whitelist → RateLimit → Dedup
      → DispatchStage(60)（分发：EventDispatcher → 平台 Handler，如 GroupMessageHandler）
      → ResultDecorate(70) → Respond(80) → llm-chat(85)（LLM 触发）
```

### 6.2 出站
```
核心产生动作（LLM 回复 / 定时推送 / 主动搭话 / 插件动作）
  → XuanJiMessage（普通话内容）
  → api.XuanJiMessageSender（统一出口）
      → 按 XuanJiBot.platform 找到对应适配器实现
      → 适配器转成平台 API 调用发出
```

## 7. 适配器契约（接入新平台 6 步）

新平台（如 KOOK）接入**只需 6 步，核心零改动**：

| 步骤 | 动作 | 落点 |
|---|---|---|
| 1 | 实现**事件转换器**：平台 JSON → `XuanJiEvent`（含 XuanJiEventType 映射、用户/群提取、消息链转换） | `adapter-xxx/converter/*` |
| 2 | 实现 **`api.XuanJiMessageSender`**：`XuanJiMessage`/动作 → 平台 API | `adapter-xxx/sender/*` |
| 3 | 声明 **`XuanJiBot.capabilities`**（平台能力枚举） | `adapter-xxx/bot/*` |
| 4 | 注册 **`BotPushSender`**（定时推送通道） | `adapter-xxx/sender/*` |
| 5 | 实现**连接生命周期**（WS/Webhook 拉起、心跳重连）并把事件喂给 `BotPipeline` | `adapter-xxx/ws` / `webhook` |
| 6 | 装配进 `xuanji-starter`（加 pom 依赖 + 配置开关） | `starter/pom.xml` |

## 9. 设计原则回顾

1. **强内聚、弱依赖**：核心只认 `XuanJiEvent`/`XuanJiMessage`/`XuanJiMessageSender`，平台差异全部隔离在适配器。
2. **进出同一门语言**：收到的富文本数组 = 回给平台的富文本数组（`XuanJiMessage`）。
3. **编译期穷尽**：`sealed` 元素类型保证新增元素强制所有转换器补全。
4. **能力自声明**：核心通过 `XuanJiBot.capabilities` 决定动作降级策略。
5. **透传兜底**：`platformData`/`Passthrough` 元素承接平台特有内容，保证未知元素不丢。
