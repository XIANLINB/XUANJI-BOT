# 璇玑（XuanJi）架构说明

> 面向维护者 / 高级开发者。本文档描述框架的整体架构：模块划分、事件管线、存储体系、适配器、AI 引擎与安全设计。
> 若想开发插件，请阅读《插件开发完整指南》；若想使用框架，请阅读《使用手册》。

---

## 一、总体架构

璇玑是一个 **Spring Boot 4 + 插件化（PF4J）+ 多平台适配** 的机器人框架。所有消息/事件从平台进入后，统一转换为内部事件模型，流经「事件分发管线」处理后，最终由命令系统 / 插件 / AI 引擎消费并产出回复。

```
                 ┌────────────────────────────────────────────────┐
                 │                 Web 控制台（前端 Vue3）          │
                 │   http://localhost:8668/xuanji/console/        │
                 └──────────────────────┬─────────────────────────┘
                                        │ /xuanji/api/v1/**
                 ┌──────────────────────▼─────────────────────────┐
                 │            xuanji-console-server（控制台后端）   │
                 └──────────────────────┬─────────────────────────┘
                                        │
   ┌───────────────┐    ┌───────────────▼───────────────┐    ┌─────────────┐
   │ QQ WebSocket  │    │      xuanji-adapter-qqbot     │    │  Webhook    │
   │ 长连接(沙箱/正式)│───▶│  统一事件模型 + 事件去重 + 类型化│◀───│  Ed25519签名 │
   └───────────────┘    └───────────────┬───────────────┘    └─────────────┘
                                        │ XuanJiEvent（统一内部事件）
                 ┌──────────────────────▼─────────────────────────┐
                 │             xuanji-core 事件分发管线            │
                 │  whitelist(20)→dedup(25)→rate-limit(30)→       │
                 │  content-safety(40)→llm-audit(41)→pre-process(50)│
                 │  →dispatch(60)→result-decorate(70)→respond(80) │
                 │  →llm-chat(85)                                  │
                 └──────┬──────────────┬──────────────┬───────────┘
                        │              │              │
                ┌───────▼─────┐ ┌──────▼──────┐ ┌─────▼───────────┐
                │ 命令系统     │ │ 插件(PF4J)   │ │ AI 引擎(xuanji-llm)│
                │ @Command     │ │ 热加载       │ │ LLM/工具/Agent/  │
                │ @GroupMessage│ │ PluginServices│ │ MCP/记忆/RAG/审核│
                └─────────────┘ └─────────────┘ └─────────────────┘
                                        │
                 ┌──────────────────────▼─────────────────────────┐
                 │          三级 H2 存储 + 定时任务中心            │
                 │  框架库 / 日志库 / 每机器人实例库               │
                 └─────────────────────────────────────────────────┘
```

## 二、模块划分

| 模块 | 职责 |
|---|---|
| `xuanji-api` | SPI 接口层：注解（`@Command`/`@Arg`/`@XuanJiPlugin`…）、消息元素（`XuanJiMessageElement`）、媒体接口、管线接口、插件门面（`PluginServices`）、类型化返回对象 |
| `xuanji-sdk` | SDK 抽象：`Bot` 接口、事件类（`GroupMessageEvent`/`PrivateMessageEvent`/`MessageEvent`）、消息链 |
| `xuanji-core` | 核心内核：事件分发管线、命令系统、插件管理（PF4J）、权限体系、存储抽象（三级 H2）、安全、发送器 |
| `xuanji-llm` | AI 能力引擎：LLM 供应商、对话、工具调用、Agent、MCP、记忆、RAG 知识库、多模态、TTS、图文卡片渲染、AI 审核、用户画像、主动搭话、日报/摘要 |
| `xuanji-scheduler` | 定时任务中心：cron 调度、HTTP 任务、机器人推送任务、归档/群状态同步系统任务 |
| `xuanji-adapter-qqbot` | QQ 官方适配器：WebSocket/Webhook 双接入、事件转换、消息发送、API 网关（`QqApiService`）、限频、熔断 |
| `xuanji-console-server` | 控制台后端：REST API（统一前缀 `/xuanji/api/v1`）、鉴权（PIN）、操作审计 |
| `xuanji-console` | 控制台前端：Vue3 + Naive UI，构建产物同步到 starter 静态资源 |
| `xuanji-starter` | 启动器：主类、装配、机器人配置读写、首启引导（Setup） |
| `xuanji-plugin-*` | 插件模块（demo / test / groupnotify） |

依赖方向：`starter → console-server/scheduler/llm/adapter → core → sdk/api`；插件只依赖 `sdk + api`（provided）。

## 三、事件分发管线

所有平台事件统一转换为 `XuanJiEvent` 后进入管线，按 `order` 升序依次经过各阶段（`PipelineStage`），阶段可 `proceed()` 放行或 `ABORT` 拦截。

| order | 阶段 | 职责 |
|---|---|---|
| 10 | waking-check | 预留占位（唤醒检查） |
| 20 | whitelist | 白名单/黑名单：**黑名单一票否决** + 主人/超管放行；sender 缺失时从 `platformData` 兜底提取用户身份 |
| 25 | dedup | 幂等去重：优先用事件 ID（`xuanji_dedup` 表跨实例幂等），缺失时退化为「发送者+类型+内容」内容键；本地 TTL 5 分钟 + DB 双保险 |
| 30 | rate-limit | 每用户冷却限流（配置驱动：`rate_limit_enabled` 开启才生效，默认关闭） |
| 40 | content-safety | 内容安全检查（当前为 P3 预留占位） |
| 41 | llm-audit | AI 审核（`LlmAuditStage`，LLM 过审，违规拦截） |
| 50 | pre-process | 预处理：事件解析、上下文准备 |
| 60 | dispatch | **事件分发**：把事件路由给命令系统 / 插件监听器 |
| 70 | result-decorate | 结果装饰（预留） |
| 80 | respond | 回复通道（预留） |
| 85 | llm-chat | LLM 对话（`LlmChatStage`）：非命令消息进入 AI 对话链路 |

另有横切阶段：`GroupActivityStage`（主动搭话）、`UserProfileStage`（用户画像），在管线外按业务触发。

管线采用「事件驱动 + 虚拟线程」模型（Spring Boot 4 默认开启虚拟线程），单事件处理不阻塞其他事件。

## 四、QQ 官方适配器（xuanji-adapter-qqbot）

### 4.1 双接入模式

- **WebSocket 长连接**（推荐，无需公网）：`QqBotWsClient` / `GatewayService` 维护 QQ 开放平台 WS 网关连接，支持沙箱/正式环境；断线自动重连。
- **Webhook**：`WebhookServiceImpl` 接收平台回调，校验 **Ed25519 签名**与 `X-Trace-ID` 去重后进入管线。

### 4.2 关键组件

| 组件 | 职责 |
|---|---|
| `QqEventConverter` | 平台原始报文 → 统一 `XuanJiEvent`（消息/系统事件） |
| `QqMessageConverter` | 内部消息链 → QQ 消息报文（含 markdown/keyboard/ark/富媒体） |
| `QqXuanJiMessageSender` | `PlatformActions` 各动作 handler：发消息、群管（禁言/撤回/审批）、入群申请列表、信息查询 |
| `QqApiService` | QQ API 网关：token 获取、REST 调用、**熔断**、错误解析透传（500/504 透传平台 message/code/traceId） |
| `AccessTokenService` | 机器人访问令牌获取与刷新 |
| `QqApiRateLimit` | **QPS/QPM 分桶限频**：按接口分类，429 时自动降档兜底 |
| `RobotRegistry` | 多机器人注册表：按 appId 定位机器人实例 |

### 4.3 多机器人

一个框架管理 N 个 QQ 机器人：每个机器人独立 appId/appSecret、独立 WS 连接、独立实例库（`data/qqbot/<appid>/`）。事件统一带 `botKey`，插件动作必须传事件所属 `botKey`（`e.getBotId()`），空串回退第一个机器人。

## 五、存储体系

### 5.1 三级 H2 数据库

| 库 | 路径 | 内容 |
|---|---|---|
| 框架库 | `data/xuanji/data/xuanji.mv.db` | 全局配置、权限、插件 KV、事件、操作日志等 |
| 日志库 | `data/xuanji/xuanji.log.mv.db` | 全链路日志 |
| 每机器人实例库 | `data/qqbot/<appid>/data/<appid>.mv.db` | 该机器人的群、用户、成员、消息记录 |

H2 采用 `AUTO_SERVER=TRUE`（支持本机多连接），HikariCP 连接池，启动自动建表/升级（`DatabaseInitializer` / `BotSchemaProvider`）。

### 5.2 存储抽象

- `PlatformDataProvider`：平台数据访问抽象（群列表/成员/消息/趋势/操作日志），适配器实现，控制台通过它读取各实例库数据。
- `PluginKvStore` / `PluginStorageService`：插件 KV 存储（`xuanji_plugin_kv`，按插件 ID 隔离）。
- `BotArchiveService`：机器人档案（群档案、用户档案）。
- `MessageEventRecorder`：消息入库与撤回标记。
- 备份：在线导出 zip + 恢复前自动快照（`BackupController`）。

## 六、AI 引擎（xuanji-llm）

| 子模块 | 职责 |
|---|---|
| `provider` | 供应商抽象：OpenAI 兼容协议 / 各家（含 GLM-4V 图片理解等） |
| `chat` | 对话链路（`LlmChatStage`）、冷却竞态控制、回复通道 |
| `tool` | 工具调用（内置：查时间/查天气/掷骰子/群统计…，`@LlmTool` 注册） |
| `agent` | Agent 自主会话（多步任务规划、跨消息上下文） |
| `mcp` | MCP 客户端接入，工具库无限扩展 |
| `memory` | 长期记忆（跨重启持久化） |
| `kb` | 知识库 RAG（上传文档 → 向量检索回答） |
| `persona` | 人格扮演（内置落落/清璃模板） |
| `profile` | 用户画像（自动提炼常聊用户性格与喜好） |
| `audit` | AI 审核（`LlmAuditStage`，违规自动拦截） |
| `proactive` | 主动搭话（群冷场活跃气氛，`GroupActivityStage`，可配置防骚扰） |
| `multimodal` | 图片理解 / 文生图 |
| `tts` | 语音合成 |
| `render` | 图文卡片渲染（HtmlRenderService，Playwright） |
| `summary` | 日报 / 会话摘要 |
| `scheduling` | 自然语言建定时任务 |

管线中的 `llm-chat`（order=85）负责把非命令消息接入 AI 对话；`UserProfileStage` 在后台维护用户画像。

## 七、插件系统

- **PF4J 3.15 + Spring 子容器隔离**：每个插件独立 `URLClassLoader` + 独立 Spring 子容器，插件间/插件与框架间类隔离。
- **CopyingJarPluginLoader（Windows jar 解锁）**：加载时把插件 jar 复制到 `.work/copy-*.jar` 运行副本，热重载时释放文件句柄，避免 Windows 下"文件被占用"。
- **插件管理**（`XuanJiPluginManager`）：`enablePlugin` / `disablePlugin` / `reloadPlugin` 热启停；插件状态持久化，重启后恢复。
- **插件 API**：`@XuanJiPlugin` 声明元信息 + 静态命令类；`@Command`/`@Arg` 命令；`@GroupMessage`/`@PrivateMessage`/`@OnMessage`/`@GroupEvent`/`@PrivateEvent` 事件监听；`PluginServices` 能力门面（发消息/LLM/群管/信息查询，类型化返回）；`PluginStorage` 持久化；`PluginConfigProvider` 配置面板。
- **命令解析**：`@Arg` 空格 token 解析、@占位自动剥离、类型转换；`getMentionedUserIds()` 由框架过滤机器人/自己。

> 框架职责边界：**框架只解析与下发足够全的字段，不做任何业务判定**（如审批、禁言决策），判定由插件实现。框架负责解析、过滤、权限校验、结果透传。

## 八、安全设计

| 层面 | 机制 |
|---|---|
| 控制台登录 | PIN 口令（PBKDF2 哈希存储，不可逆）；会话管理（`SessionStore`） |
| 机器人密钥 | AppSecret 加密落盘（`CredentialCipher`），控制台只显示掩码 |
| Webhook 回调 | **Ed25519 签名验签** + `X-Trace-ID` 去重 |
| 权限体系 | L4 黑名单一票否决 → L0 主人/超管放行 → 平台角色（owner/admin/member）→ 权限点（`@RequireRole`） |
| 消息安全 | 命令角色限制（`roles`）、`@RateLimit` 限流、`@MessageFilter` 过滤、管线 `rate-limit`/`llm-audit` |
| 操作审计 | 全链路操作日志：消息、管理动作（禁言/撤回/审批）、机器人操作等写入实例库 `qqbot_op_log`；控制台来源操作人=来源 IP |
| 日志脱敏 | `LogMasker` 对敏感 key 打码 |
| 网络调用 | QQ API 熔断（异常自动熔断降级）+ QPS/QPM 分桶限频（429 降档兜底）+ 超时控制 |

## 九、定时任务中心（xuanji-scheduler）

- `TaskSchedulerService`：cron 调度核心（`CronUtil`）。
- 任务类型：`BotPushJobExecutor`（定时推消息到群/用户）、`HttpJobExecutor`（定时 HTTP 请求）、`JobExecutor`（通用）。
- 系统任务：`BotArchiveSystemJobs`（归档清理）、`BotGroupStateSyncSystemJobs`（群状态同步）。
- `SchedulerAdminApi`：控制台可视化管理。

---

## 十、控制台前后端

- **后端** `xuanji-console-server`：18 个 Controller（机器人/消息/群/权限/插件/定时/数据/监控/AI/操作日志…），统一前缀 `/xuanji/api/v1`，经 `@XuanJiApi` 注解自动装配路由。
- **前端** `xuanji-console`：Vue3 + Vite + Naive UI + vue-router，构建产物同步到 `xuanji-starter/src/main/resources/static/xuanji/console/`，由 starter 直接托管（单端口部署）。
- **流式推送**：`ConsoleStreamController`（SSE/WS）实时推送消息/事件到控制台。

## 十二、打包与发布

- 源码构建：`mvn clean package -DskipTests`（JDK 25+ / Maven 3.9+）。
- 发布包：`scripts/` 提供分平台打包脚本（win/linux），产出**自带精简 JRE** 的发布包（用户无需安装 JDK）。详见 `scripts/BUILD-USAGE.txt`。
- 插件部署：插件 jar 放 `plugins/`，控制台热加载。
- 前端产物：`npm run build` 后需同步 `xuanji-console` 产物到 starter 静态资源目录。
