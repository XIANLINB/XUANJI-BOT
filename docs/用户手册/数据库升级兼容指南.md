# 数据库升级兼容指南

> 适用版本：璇玑框架 v3.3+（2026-08 收敛后）
> 核心目标：**用户升级框架后，旧数据 100% 保留**，且框架可长期演进。

---

## 一、为什么升级不会丢数据

框架采用「**数据与代码分离**」架构，升级只替换程序（jar/class），数据文件原样保留：

| 数据层 | 位置 | 升级行为 |
|---|---|---|
| 框架库 | `data/xuanji/xuanji.mv.db` | `CREATE TABLE IF NOT EXISTS` → 已存在则跳过，数据不动 |
| 平台共享库 | `data/qqbot/qqbot.mv.db` / `data/onebot/onebot.mv.db` | 同上 |
| per-bot 实例库 | `data/qqbot/{appId}/data/{appId}.mv.db` | 同上（QQ/OneBot 各自） |
| 媒体文件 | `data/xuanji/media/` | 纯文件系统，升级不触碰 |
| 插件 | `plugins/*.jar` + `xuanji_plugin_kv` 表 | 替换 jar 即可，插件数据保留 |

**启动流程**（`DatabaseInitializer`）：
1. 全部 `CREATE TABLE IF NOT EXISTS ...`（表已存在 → 跳过，数据保留）
2. `migrateLegacyTables()`：按需增量迁移（只对旧库生效，新库无操作）
3. 启动完成，旧数据可用

## 二、三条铁律（升级开发时必须遵守）

### 铁律 1：只增不改
- **可以**：新增表、新增列、新增索引
- **禁止**：删除列、改列名、改列类型（会毁旧数据）

### 铁律 2：建表建列必须 IF NOT EXISTS
```sql
-- ✅ 新表（旧库自动补建）
CREATE TABLE IF NOT EXISTS xuanji_new_table (...);

-- ✅ 给旧表加列（必须 IF NOT EXISTS，重复启动不报错）
ALTER TABLE xuanji_bot ADD COLUMN IF NOT EXISTS instance_id VARCHAR(128);

-- ❌ 危险写法（旧库直接抛错）
ALTER TABLE xuanji_bot ADD COLUMN instance_id VARCHAR(128);
```

### 铁律 3：真要改结构 → 走迁移（新增列 + 回填 + 旧列兜底）
参考框架已内置的迁移先例（`migrateLegacyTables()`）：

```java
// 1. 加新列（IF NOT EXISTS）
jdbc.execute("ALTER TABLE xuanji_bot ADD COLUMN IF NOT EXISTS instance_id VARCHAR(128)");

// 2. 从旧列回填新列（只填空值，不覆盖已有数据）
jdbc.execute("UPDATE xuanji_bot SET instance_id = bot_identifier WHERE instance_id IS NULL OR instance_id = ''");

// 3. 旧列保留（DROP 前必须确认所有逻辑已切换）；兜底：列不存在时 H2 抛错被忽略
try { jdbc.execute("ALTER TABLE xuanji_bot DROP COLUMN IF EXISTS bot_identifier"); } catch (Exception ignored) {}
```

## 三、迁移模板（新增表 / 加列时照抄）

在 `DatabaseInitializer.init()` 的建表区**追加**（不要插到中间）：

```java
// ===== v3.4 新增：xxx 表 =====
jdbc.execute("""
    CREATE TABLE IF NOT EXISTS xuanji_xxx (
        id BIGINT AUTO_INCREMENT PRIMARY KEY,
        ...
    )
""");
```

在 `migrateLegacyTables()` 的**末尾**追加旧库迁移：

```java
// v3.3 → v3.4：旧表 xxx 迁移
try {
    jdbc.execute("""
        INSERT INTO xuanji_new_table (...)
        SELECT ... FROM xuanji_old_table
        WHERE NOT EXISTS (SELECT 1 FROM xuanji_new_table WHERE ...)
    """);
} catch (Exception ignored) { /* 新库无旧表，跳过 */ }
```

## 四、per-bot 实例库升级要点

per-bot 库（`QqBotSchemaProvider.initSchema` / OneBot 对应）同样 `CREATE TABLE IF NOT EXISTS`：
- 新增表 → 追加建表语句即可，所有机器人实例库惰性补建
- **注意**：删机器人再重加会清空该 bot 目录并重建——这是**预期行为**（删除=彻底删除），不是升级问题
- 升级时**千万不要**删 `data/` 目录

## 五、升级自检清单（发布前）

- [ ] 所有新表/新列均 `IF NOT EXISTS`
- [ ] 没有删除/改名任何既有列
- [ ] 旧数据迁移用 `NOT EXISTS` 防重复回填
- [ ] 用**旧版本 data/ 目录**实测一次启动（能启动、数据在、新功能可用）
- [ ] 修改了消息表等核心表时，检查控制台各页面数据正常
